# Выкат api

С 2026-10-11 бэкенд живёт на одном сервере Selectel (`wh-rules-api`, 31.129.57.24), всё в Docker:
Caddy (TLS, единственное, что слушает снаружи) → API → PostgreSQL. Файлы — `deploy/` этого
репозитория, на сервере `/opt/wh-rules/` с кодом в `app/`. Подробности (первый запуск сервера,
бэкапы, cron) — README, раздел «Deploy». Yandex Cloud Functions и YDB больше нет: всё, что о них
написано где-то ещё, устарело.

**Выкатывает владелец.** Агенту выкат запрещён (классификатор режет ssh с правками на сервере), и
обходить это нельзя. Агент готовит всё до команды и проверяет после; саму команду отдаёт владельцу.

## 1. До выката — у агента

```bash
git status --short          # чисто: выкатывается коммит, не рабочее дерево
npm run typecheck && npm test
```

- Выкатывается **закоммиченный** ref (по умолчанию `main`); скрипт отказывается при грязном дереве.
- **Схема меняется?** Новый файл в `migrations/` (`00N_….sql`), никогда не правка уже
  применённого. Миграции применяются при старте контейнера API (`npm run migrate` в entrypoint).
  Порядок релиза — **схема, потом API, потом клиент** (README «Changing the schema»): сервер, который
  читает колонку, которой нет в базе, роняет каждый запрос к ней.
- **Новая переменная окружения?** Её добавляет владелец в `/opt/wh-rules/.env` на сервере до
  выката (пример — `deploy/.env.prod.example`); агент секреты не видит и не пишет.
- Меняется контракт с фронтом (`domain/game.ts`, конверт партии, auth) — сначала API, фронт после.

## 2. Выкат — команда владельцу

Из хаба:

```
! bash wh11ed-api/deploy/release.sh
```

(`release.sh <ref>` — ветка или коммит вместо `main`.) Скрипт: `git archive` ref'а → новый `app/`
на сервере (прежний остаётся `app.prev`), `docker compose -f docker-compose.prod.yml up -d --build api`,
затем проверки (п. 3). Пишет ревизию в `app/REVISION`.

## 3. После — проверка (агент читает вывод скрипта)

Скрипт сам проверяет два адреса:
- `https://api.wh-rules.ru/health` — сервер жив (базу не трогает);
- `https://api.wh-rules.ru/broadcast/<несуществующий>` → **404** — Postgres ответил.

Сверх этого, по задаче: то, что меняли (новый эндпоинт, лимит, поле) — curl'ом или с сайта. Чтение
логов с сервера разрешено:

```bash
ssh -i ~/.ssh/wh_rules_vps wh@31.129.57.24 "cd /opt/wh-rules && docker compose -f docker-compose.prod.yml logs --tail 50 api"
```

## 4. Откат

```
! bash wh11ed-api/deploy/release.sh --rollback
```

Возвращает `app.prev` (выкаченный уходит в `app.bad`) и пересобирает API. **Миграцию это не
откатывает**: колонка, добавленная новой версией, останется — поэтому миграции пишутся так, чтобы
старый код с ними жил (добавлять, а не переименовывать и не удалять в том же релизе).

## Что помнить

- Пуш api — только по команде владельца; выкат — только его командой.
- Журнал ошибок прода и очередь отзывов читаются скриптами в контейнере (скилы `feedback-triage`,
  память «Журнал ошибок прода»), не через этот скил.
